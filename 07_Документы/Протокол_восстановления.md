# Протокол восстановления

**Проект и версия:** ОРБИТА 1.0. **Исполнитель:** Сидоров Егор Денисович, 4ИСИП-723. **Дата проверки:** 07.11.2026.

**Резервная копия:** `02_Данные/резервная_копия/orbita-2026-11-07-18-48-17.db` (+ манифест `.json`), создана командой `npm run backup` (SQLite `VACUUM INTO`, 244 КБ).
**Состав копии:** вся БД: users 26, categories 6, events 63, registrations 727, messages 0.
**Отдельная среда восстановления:** файл `backups/restore-check/restored.db` (новая БД, рабочая `data/orbita.db` не затрагивается).
(Копия `orbita-2026-11-07-18-39-57.db` в той же папке — более ранняя, снята с демонстрационной базы после съёмки экранов; в проверках не используется.)

## Выполненные действия

1. `node scripts/db.js reset` — чистая рабочая БД с учебными данными.
2. `node scripts/backup.js backup` — создана копия и манифест с числом записей.
3. `node scripts/backup.js restore` — копия скопирована в отдельную БД, открыта приложением и проверена (вывод — `02_Данные/вывод_restore.txt`, снимок `восстановление_консоль.png`).

## Проверка

| Проверка | Фактический результат |
|---|---|
| Запуск приложения | БД открывается модулем приложения, каталог читается: «найдено 60 (всего опубликованных), на странице 9» |
| Количество записей и связи | users 26, categories 6, events 63, registrations 727, messages 0 — совпадают с манифестом; `PRAGMA integrity_check` = ok; `PRAGMA foreign_key_check` — нарушений нет |
| Чтение и изменение данных | запись пользователя `andreev` на мероприятие: занято 9 → 10, отмена: 9 |
| Права доступа | в восстановленной БД сохранены триггеры и индексы: повторная запись отклонена («уже зарегистрированы»); превышений лимита нет (событий с превышением: 0) |
| Основной пользовательский сценарий | запись и отмена выполнены функциями приложения над восстановленной БД |

**Вывод и ограничения.** Копия полностью воспроизводит данные и ограничения. Проверка выполнена скриптом на одной машине; восстановление через веб-интерфейс, права по HTTP на восстановленной базе и работа копии на другом компьютере не проверялись. Резервные копии содержат хеши паролей и учебные данные — в реальной эксплуатации их нужно защищать.
