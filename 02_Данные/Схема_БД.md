# Схема базы данных

СУБД SQLite 3.53 (встроена в Node.js 24). Схема создаётся миграциями `migrations/001_init.sql`, `002_indexes.sql` (копии — в этой папке). Диаграмма: `er_диаграмма.svg`, `04_Проверки/снимки_экрана/er_диаграмма.png`.

## Таблицы

| Таблица | Назначение | Ключевые связи |
|---|---|---|
| users | учётные записи: логин, имя, e-mail, хеш пароля, роль | — |
| categories | шесть категорий мероприятий | — |
| **events** | мероприятия: название, описание, формат, город, место, начало/конец, лимит, цена, статус | category_id → categories (RESTRICT); organizer_id → users (RESTRICT) |
| **registrations** | регистрации: статус active/cancelled, отметка присутствия | event_id → events (CASCADE); user_id → users (CASCADE) |
| sessions | сеансы входа и CSRF-токены (служебная) | user_id → users (CASCADE) |
| messages | сообщения формы «Контакты» | — |
| access_log | журнал обращений (время, метод, маршрут, статус, длительность) | — |

Предметные сущности темы: **categories, events, registrations** (три связанные, помимо учётных записей).

## Ограничения

| Ограничение | Реализация |
|---|---|
| Лимит участников 1…100000 | `CHECK (capacity BETWEEN 1 AND 100000)` |
| Статусы и роли — перечисления | `CHECK (status IN …)`, `CHECK (role IN …)` |
| Окончание позже начала, формат даты | `CHECK (ends_at > starts_at)`, `GLOB 'ГГГГ-ММ-ДДTЧЧ:ММ'` |
| Цена не отрицательна | `CHECK (price >= 0)` |
| Логин и e-mail уникальны без учёта регистра | `UNIQUE … COLLATE NOCASE` |
| **Одна активная регистрация пользователя на событие** | частичный `UNIQUE INDEX ux_registrations_active (event_id, user_id) WHERE status = 'active'` |
| **Активных регистраций не больше лимита** | триггеры `trg_reg_insert`, `trg_reg_reactivate` (ошибка `EVENT_FULL`) |
| Запись только на опубликованное событие | те же триггеры (`EVENT_CLOSED`) |
| Лимит нельзя уменьшить ниже занятых мест | триггер `trg_event_capacity` (`CAPACITY_BELOW_ACTIVE`) |
| События создают только организаторы и админы | триггер `trg_event_organizer_ins` (`ORGANIZER_ROLE_REQUIRED`) |

## Политика удаления

- Удаление мероприятия удаляет его регистрации (CASCADE); приложение при этом запрещает удалять события с активными регистрациями (сначала отмена).
- Удаление пользователя удаляет его регистрации и сеансы (CASCADE); пока у пользователя есть события, удалить его нельзя (RESTRICT).
- Удаление категории с мероприятиями запрещено (RESTRICT).
- Отмена регистрации — не удаление: строка остаётся со статусом `cancelled` (история), место освобождается, так как считаются только `active`.

## Воспроизведение

```bash
npm run db:reset                       # рабочая БД: data/orbita.db
node scripts/backup.js restore         # отдельная пустая БД из копии + проверки (backups/restore-check)
npm test                               # на каждом запуске схема создаётся в новой временной БД
```
