# ОРБИТА — платформа мероприятий

Учебная практика УП.09.01, тема №6 «Мероприятия». Студент: Сидоров Егор Денисович, группа 4ИСИП-723.
Обязательное правило темы: **число активных регистраций не превышает лимит участников**.

Сайт для поиска мероприятий и регистрации на них: каталог с поиском и фильтрами, личный кабинет участника, панель организатора (создание и редактирование событий, список участников, свободные места).

## Версии средств

| Средство | Версия |
|---|---|
| Node.js | 24.19.0 (нужен 22.13 и новее: используется встроенный модуль `node:sqlite`) |
| СУБД | SQLite 3.53 (встроена в Node.js, отдельная установка не нужна) |
| Зависимости npm | нет (`npm install` не требуется) |
| Браузер для проверки | Microsoft Edge (Chromium) |

## Установка и запуск

```bash
cd 01_Проект
cp .env.example .env        # Windows PowerShell: Copy-Item .env.example .env
npm run db:reset            # создать БД миграциями и загрузить учебные данные
npm start                   # http://localhost:3000
```

Если файл `.env` не создан, действуют значения по умолчанию (порт 3000, БД `data/orbita.db`); на пустой базе учебные данные загружаются сами (`AUTO_SEED=1`).

## Конфигурация (`.env`)

| Переменная | Значение по умолчанию | Назначение |
|---|---|---|
| `PORT`, `HOST` | 3000, 0.0.0.0 | адрес сервера (0.0.0.0 — доступ из локальной сети) |
| `DB_PATH` | data/orbita.db | файл базы данных |
| `SITE_URL` | http://localhost:3000 | адрес для canonical, sitemap.xml и cookie `Secure` (при https) |
| `DEBUG_ERRORS` | 0 | 1 — показывать подробности ошибок (только при разработке) |
| `AUTO_SEED` | 1 | загрузить учебные данные в пустую БД |
| `SEED_PASSWORD` | Orbita-demo1 | пароль учебных учётных записей |

## Команды

| Команда | Действие |
|---|---|
| `npm run db:reset` | удалить рабочую БД, применить миграции, загрузить данные (26 пользователей, 63 мероприятия, 727 регистраций) |
| `npm run db:migrate` | применить только новые миграции |
| `npm test` | 60 автотестов (запускают сервер на временной БД) |
| `npm run bench` | замеры до и после оптимизации |
| `npm run backup` | резервная копия БД (`backups/`, переменная `BACKUP_DIR`) |
| `npm run restore` | восстановление копии в отдельную БД и проверки |

## Структура

```

src/server.js          контекст запроса, сеансы, CSRF, ошибки, журнал обращений

src/auth.js            scrypt, сеансы, CSRF-токены, ограничение частоты входа
src/ui.js, html.js     общие компоненты и безопасный шаблонизатор
src/routes/            public, auth, account, organizer (+ admin)
migrations/            001_init.sql (схема, триггеры), 002_indexes.sql
scripts/               db, test, bench, backup, traffic, seo-check
public/                CSS, JS, шрифты, фото
```

## Как проверить правило темы

1. Войдите как `ivanova`, откройте мероприятие с заполненным лимитом (метка «Мест нет», например «Мастер-класс по SQL») — кнопка недоступна.
2. Откройте мероприятие со свободными местами и зарегистрируйтесь; повторная попытка даст сообщение «Вы уже зарегистрированы».
3. В «Мои регистрации» отмените запись — место освободится (счётчик на странице мероприятия увеличится).
4. Защита на уровне БД проверяется тестами A1–A11 (`npm test`), в том числе параллельными процессами.

## Безопасность

Пароли — scrypt с солью; сеанс — случайный идентификатор в cookie `HttpOnly; SameSite=Lax` (в БД хранится только SHA-256); CSRF-токен во всех POST-формах; SQL-запросы параметризованы; весь вывод экранируется; заголовки CSP и др.; ограничение попыток входа. Секреты в репозиторий не попадают (`.env` в `.gitignore`).
